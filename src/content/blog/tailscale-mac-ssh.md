「MacBookから、別のMacBookにSSH接続できる？」。今回の出発点は、この疑問でした。同じWi-Fiならつながりそう。でも、外出先から自宅のMacに入りたいときは、どうするんだろう。

試したのは、両方のMacにTailscaleを入れて、macOS標準のSSHを使う方法です。設定を進めて、最後は接続できました。目標は、手元のターミナルから自宅Macにログインすること。持ち歩くMacと家に置くMac、それぞれで行うことを順番にまとめます。

<p class="proof">設定日：2026年11月10日。外出用MacはAppleシリコン・macOS 26.5、Tailscale 1.104.5。外出用のインストール、VPN接続、自動起動の登録は実画面で確認しました。自宅側の設定とSSH接続成功は本人の確認に基づきます。別回線・再起動後の再接続や長時間の安定性までは検証していません。</p>

掲載画像は外出用Macで撮影した実画面です。自宅Macのリモートログイン・スリープ設定画面は今回撮影していません。個人情報は黒塗りまたは画像の切り取りで除外しています。

## まず、2台で役割が違う

**外出用Macは接続する側、自宅Macは接続を受ける側**です。Tailscaleは両方に入れますが、「リモートログイン」をオンにするのは自宅Macです。

Tailscaleで端末間の通信経路を作り、その上でSSHを使います。VPNが接続済みでも、SSHの受け口が自宅Macで有効になっていなければログインできません。[Tailscaleの公式説明](https://tailscale.com/docs/how-to/connect-to-devices)でも、接続先でSSHなどのサービスを動かす必要があると説明されています。

ここでできるのは、自宅Macのターミナル操作です。デスクトップ画面をそのまま操作する画面共有とは別です。また、本記事ではTailscaleの独立した機能である「Tailscale SSH」ではなく、macOS標準のSSHを使います。

準備するのは、インターネットにつながる2台のMac、Tailscaleにログインするアカウント、自宅Macのログイン情報と電源アダプタ。インストールや権限の許可に管理者認証が必要な場合があります。

2026年11月10日時点で、Personalプランは非商用の個人利用向けの無料プランです。個人のMacでも業務で使う場合は、用途に合うプランを[公式料金ページ](https://tailscale.com/pricing)で確認してください。

## 1．両方のMacにTailscaleを入れる

[公式のMac用ダウンロードページ](https://tailscale.com/download/mac)を開き、インストーラーをダウンロードします。今回は公式サイト配布のpkg版を使いました。ダブルクリックして画面の案内に従い、アプリケーションフォルダのTailscaleを開きます。

初期設定ではネットワーク拡張とVPN構成の許可が必要です。今回の環境では、システム設定の「一般」→「ログイン項目と機能拡張」→「ネットワーク機能拡張」でTailscaleの拡張を確認できました。場所や表示はOSによって変わるため、見つからないときは[公式のmacOS導入手順](https://tailscale.com/docs/install/mac)に戻ります。

<figure><a href="/articles/tailscale-mac-ssh/network-extension.webp" target="_blank"><img src="/articles/tailscale-mac-ssh/network-extension.webp" width="800" height="791" alt="Tailscaleのネットワーク機能拡張が有効になった実画面" loading="lazy" decoding="async"></a><figcaption>① 両方のMacで確認。Tailscale Network Extensionのスイッチが右側になっていることを確認します。</figcaption></figure>

両方のMacで、同じアカウントを使ってログインします。今回使ったのはGitHubログインですが、読者の方もGitHubに合わせる必要はありません。

ここでひとつ、**ブラウザでログインしただけでは、端末の登録がまだ終わっていない**場面がありました。「Connect device」の画面が出たら、表示されている端末名と接続先ネットワークを確かめ、「Connect device to tailnet」を押します。tailnetは、自分の端末が参加するTailscaleのネットワークです。

**成功の目印：** アプリに「Connected」と表示され、両方の端末が一覧に出ること。片方しか出ない場合は、もう片方の登録とアカウントを確認します。

## 2．自宅Macでリモートログインをオンにする

自宅Macで「システム設定」→「一般」→「共有」を開き、「リモートログイン」の詳細からオンにします。「アクセスを許可」は「次のユーザのみ」にして、SSHで入る自分のユーザーを追加します。

[Appleの公式手順](https://support.apple.com/ja-jp/guide/mac-help/mchlp1066/mac)に沿った設定です。通常のログイン確認のために、フルディスクアクセスまで追加する必要はありません。

次に、自宅Macの「ターミナル」を開いて、以下を入力します。

```bash
whoami
```

**結果：** 自宅Macの短いユーザー名が1行表示されます。これがSSHコマンドのユーザー名です。TailscaleにログインしたメールアドレスやGitHub名とは別なので、ここを取り違えないようにします。

自宅MacのTailscaleアプリで、端末に割り当てられた `100.` から始まるIPアドレスも控えます。必要なのは**自宅MacのIP**です。外出用Macにも別のIPが付いています。

## 3．自宅Macを起こしておく

接続先がスリープしていると、外から使いたいときにつながりません。まずは自宅Macを電源アダプタにつなぎ、ふたを開けて置く運用にします。

「システム設定」→「バッテリー」→「オプション」で、「電源アダプタ使用時はディスプレイがオフのときに自動でスリープさせない」をオンにします。画面を消すことと、本体がスリープすることは別です。画面のロックもしておきます。[Appleのスリープ設定](https://support.apple.com/ja-jp/guide/mac-help/mchle41a6ccd/mac)

ふたを閉じて運用する方法は、今回の検証範囲に含めません。まずは開いた状態で接続できるところまで進めます。

## 4．自動起動は、設定したあとに確かめる

両方のMacで、Tailscaleの設定にある「Launch Tailscale at login」をオンにします。

ところが外出用Macでは、ここで設定できないというエラーが出ました。アプリ内の操作だけで終わりにせず、macOSの設定から追加することにしました。

1. 「システム設定」→「一般」→「ログイン項目と機能拡張」を開く。
2. 「ログイン時に開く」の「＋」を押す。
3. 「アプリケーション」からTailscaleを選び、追加する。
4. 一覧に「Tailscale」が表示されたことを確認する。

<figure><a href="/articles/tailscale-mac-ssh/login-items.webp" target="_blank"><img src="/articles/tailscale-mac-ssh/login-items.webp" width="950" height="430" alt="macOSのログイン時に開く一覧にTailscaleが追加された実画面" loading="lazy" decoding="async"></a><figcaption>③ アプリ内で自動起動を設定できない場合はこちら。「＋」から追加し、一覧にTailscaleが出れば登録完了です。</figcaption></figure>

今回、確認できたのはこの登録までです。**ログイン時の自動起動は、再起動後、誰もログインしていない状態で接続できることの保証ではありません。** 自宅Macを無人で使うなら、出かける前に再起動後の挙動も確かめてください。FileVaultのロック解除やTailscaleの起動状態などが関係するため、設定しただけでいつでも入れると思わない方がよさそうです。

## 5．外出用Macのターミナルから接続する

外出用MacでもTailscaleが「Connected」になっていることを確認します。ターミナルで、次の形のコマンドを実行します。

```bash
ssh ユーザー名@自宅MacのTailscale_IP
```

例えばユーザー名が `homeuser`、IPが `100.101.102.103` なら、こうです。**以下は説明用の例で、今回の実際の接続情報ではありません。自分の値に置き換えてください。**

```bash
ssh homeuser@100.101.102.103
```

初回は接続先のホスト鍵を信頼するか確認されることがあります。ED25519の鍵が表示された場合は、自宅Macのターミナルで次を実行すると、照合する指紋を確認できます。

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

**結果：** `SHA256:` から始まる指紋などが表示されます。外出用Macに出ている鍵の種類と指紋が一致することを確認して、`yes` を入力します。違う種類の鍵が提示されたり、ファイルが見つからない場合は、そのまま承認せず自宅側の鍵を確認してください。

パスワードを求められたら、自宅Macのログインパスワードを入力します。入力中は文字も「＊」も表示されません。

接続後に次のコマンドを実行します。

```bash
hostname
```

**成功の目印：** 自宅Macのホスト名が返ること。先に自宅Macのターミナルでも同じコマンドを実行し、比較できるように控えておくと分かりやすいです。続けて `whoami` でログインしたユーザーも確認できます。この確認方法は読者向けの手順で、今回の実行ログを掲載したものではありません。

接続を終えるときは、次を入力します。

```bash
exit
```

接続が閉じ、外出用Mac側のプロンプトに戻れば終了です。

## つながらないときは、どこまで進んだかを見る

- **端末一覧に自宅Macがない：** 両方が同じアカウントのネットワークに参加しているか、ブラウザの端末登録まで終わっているかを確認します。
- **タイムアウトする：** 自宅Macの電源・スリープ・インターネット・Tailscaleの接続状態と、入力したIPを確認します。接続を制限するネットワークルールがないかも確認します。
- **Connection refused：** 自宅Macの「リモートログイン」がオンか、接続先IPが正しいかを確認します。
- **Permission denied：** 自宅Macで実行した `whoami` のユーザー名、アクセス許可の対象、入力したパスワードを見直します。
- **ホスト鍵が変わったという警告：** 警告を消す操作を先にせず、自宅Macの再インストールや接続先の変更があったかを確認します。

VPN接続済み、端末が見える、SSHでログインできる。この3つを順に確認すると、戻る場所を見つけやすくなります。

## 最後に、家のWi-Fiを離れて試す

今回、2台の設定を進めてSSH接続できたところまで確認できました。ただし、その成功だけで、別の回線や再起動後でも同じようにつながるとまでは言えません。

外出前の仕上げとして、外出用Macをスマホのテザリングにつなぎ直し、同じSSHコマンドで試すとよさそうです。この別回線テストは今回未実施です。

自宅のMacを、手元のターミナルから使う。まずはそこまでできるようになりました。最初の確認では `hostname` のように情報を見るコマンドを使い、接続先を確かめてから作業を始めると安心です。
